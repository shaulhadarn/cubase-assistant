# Prioritized build tasks

The foundation is a separate local application repository. These are reviewable implementation tasks for subsequent milestones; no native work is implicitly enabled.

| Priority | Task                      | Acceptance evidence / dependency                                                                                                                                                                                                                                      |
| -------- | ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P0       | Durable host coordinator  | Persist intent before dispatch and results after readback; survive crash after commit; deduplicate across restarts; replay never repeats an unknown write. Keep existing core tests and add process-crash tests.                                                      |
| P0       | Windows x64 shell         | Electron sandbox/preload, runtime IPC validation, single-instance/single-writer locks, accessible keyboard flows, signed packaging plan. Run on Windows CI and a local machine; do not ship keys.                                                                     |
| P0       | Read-only native spike    | Confirm user's exact Cubase version/edition and existing license. Use a disposable, explicitly authorized project. Probe capabilities, activation lifecycle, project epochs, channel identity, units and automation; capture a compatibility fixture. No real writes. |
| P1       | Native contract and codec | Finalize lease/heartbeat/recovery operations; strict wire schemas, bounded framing/sequence/checksum, ES5 implementation and fuzz tests. Confirm virtual-MIDI routing without assuming a driver.                                                                      |
| P1       | One real reversible write | Only after P0: project-copy workflow, durable journal, proven exclusion against concurrent user/automation edits, apply/verify/restore on one supported adapter. Unknown outcomes require reconciliation. Disable unsupported versions/parameters.                    |
| P1       | OpenAI proposal provider  | Authorized credentials/data policy, managed session lifecycle, narrow inspect/propose tools, persisted tool-call deduplication, mocked failure/reconnect tests, then bounded live evaluation. AI still cannot apply.                                                  |
| P2       | Broaden compatibility     | Test per-version/edition matrix across 11–15; prefer truthful read-only or unsupported results. Generic Remote/MCU support is its own constrained adapter.                                                                                                            |
| P2       | Render and analyze        | Authorized export capture, local DSP, clipping/loudness/peak metrics and objective fixtures. Optional separate audio-capable model. No fabricated analysis.                                                                                                           |
| P3       | Loudness-matched A/B      | Calibrated comparison path, playback routing, gain matching and user evaluation. Automation edits and plugin assignment require separate designs.                                                                                                                     |

Next recommended milestone: **durable Windows host plus read-only adapter proof**, starting with one known Cubase installation. Keep `Bridge`, `ProposalProvider`, version-1 commands and the readback journal as the integration seams. A safe native write cannot be promised until race exclusion and automation detection are demonstrated.
